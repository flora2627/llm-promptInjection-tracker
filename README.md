# LLM 提示注入 · 领域追踪

一张数据驱动的**立场图**：把 prompt injection 这个领域画成签名边网络——谁继承谁、谁佐证谁、谁证伪谁。
姊妹项目是 [`../llm-jailbreak-tracker`](../llm-jailbreak-tracker)（LLM 越狱）与
[`../llm-backdoor-tracker`](../llm-backdoor-tracker)（LLM backdoor 检测），三者用同一套构建管线与同一套内容纪律，可以对照着读。

> ### 这是什么 / 不是什么
>
> **这是一名二进制安全研究者在自学 LLM 安全方向时，借助 AI 整理出来的领域索引。**
> 要解决的问题很具体：提示注入的记录**散在四个互不相通的地方**——arXiv 的 `cs.CR` 与 `cs.CL`、
> 安全研究者的个人博客、厂商的安全公告与产品文档、会议议题的幻灯片；
> 而这个领域**最承重的一批证据恰恰在非论文那一侧**，没有任何一个书目库会收它们。
> 它的用途是**快速检索与分类**——迅速定位「哪条线还在打、该先读哪篇、这篇的对手是谁」，并给出直达原文的链接。
>
> **它不是综述，不应当被当作引用来源。**
>
> - 图上每条 note、每张战线卡的裁定（「已证伪」「已反转」「未决」「已分层」）都是**编者的概括与判断**，
>   **不是原作者的表述，也不代表领域共识**。任何一条要用之前，请点开链接读原文。
> - **「常被误读」标记针对的是这些工作被转述和引用的方式，不是被标注的工作本身。**
>   恰恰相反——被标的通常正是这个领域最重要、被引最多的那几篇。
> - **「核验状态」标的是编者是否亲自核对过书目**，**不是**对其结论正确性的背书。
> - **收录漏洞披露不等于认可其严重程度评级。**本图对 CVE 有无、CVSS 高低不做加权——
>   在这个领域里，拿没拿到 CVE 与技术上开没开辟新面基本无关。
> - **整理过程有 AI 参与，会出错。**勘误请开 Issue。

## 范围

**收：**对「建立在 LLM 之上的应用」的指令层级攻击——不可信内容被拼接进可信提示后被当作指令执行。
含**直接注入与提示窃取**、**间接注入**（网页/邮件/文档/转录/issue 等数据面）、
**RAG·记忆·供应链投毒**、**agent 劫持**（工具、MCP、computer-use、浏览器 agent）、
**外泄通道与野外事故**（CVE 与一手漏洞披露）、各层防御、评测与竞赛靶场、理论与立场。

**不限于论文。**漏洞披露、博客、会议议题、竞赛靶场、厂商文档与立场文章**与论文平权入图**，
只用 kind 徽章区分。理由见下面「现状快照」里那一行：**98 条里 44 条不是论文**。

**不收（判超范围，记录在此不是漏掉）：**
- **越狱**——威胁模型是突破模型自带的 harmfulness 拒答，归 [`llm-jailbreak-tracker`](../llm-jailbreak-tracker)。
  少数横跨条目（如 `2510.09023`，标题里同时写了 jailbreaks 与 prompt injections）**两图各取一半**，
  并在双方注记里写明取的是哪一半。
- **训练期权重后门**——载体是模型参数而不是运行时数据，归 [`llm-backdoor-tracker`](../llm-backdoor-tracker)。
  边界个案：**记忆/检索库投毒本图收**（载体是数据库里的一行，不是权重）。
- **纯营销性质的厂商安全博客**（只说「我们很重视安全」而无可核实的技术内容）。

## 一分钟上手

```bash
cd notes/llm-promptInjection-tracker
python3 build.py --open      # 生成 index.html 并打开
```

无依赖，纯标准库。`index.html` 是**单文件**——数据全部内联，双击就能看。

## 目录

```
llm-promptInjection-tracker/
├── README.md          ← 本文件
├── MAINTENANCE.md     ← 维护笔记：更新流程 / schema / 图的约定 / 历史留档
├── LICENSE            ← 内容 CC BY 4.0 / 代码 MIT
├── build.py           ← 唯一的构建入口（带自检）
├── spread.py          ← 标签太挤时重排显示坐标（幂等，从 t0 重算）
├── template.html      ← 页面骨架 + CSS + 渲染器，不含数据
├── index.html         ← 生成产物，不要手改
└── data/
    ├── papers.json    ← 条目库（98） ← 主要在这里加东西
    ├── edges.json     ← 签名边（208） ← 和这里
    ├── fronts.json    ← 交火战线卡片（11）
    ├── misread.json   ← 「常被系统性误读」标记（31）
    ├── lanes.json     ← 十二条主干泳道
    └── years.json     ← 时间轴刻度 [年份, t 坐标]
```

**只改 `data/*.json`，然后跑 `build.py`。** 改样式才动 `template.html`。

## 现状快照

| | |
|---|---|
| 条目 | 98 —— **论文 54 · 非论文 44**（漏洞披露 26 · 立场 7 · 博客 5 · 竞赛靶场 3 · 议题 1 · 事件 1 · 厂商文档 1） |
| 边 | 208 —— 继承 108 · **佐证 69** · **反驳 31** |
| 战线 | 11 条交火中 |
| 引用核验 | **98 confirmed · 0 待核**（逐条拉原始页面核对） |
| 泳道 | 12 条 · 2022–2026 |
| 边数最多 | `greshake` 24 · `agentdojo` 15 · `formalize` 14 · `mdimage` 12 · `lethaltrifecta` 11 |

**三个最该先看的结构事实：**

1. **近一半条目不是论文。** 这不是凑数：Dual LLM 模式在博客里躺了两年才被做成 CaMeL；
   指令层级被绕的第一份证据是一篇博客；lethal trifecta 这条被 Meta 写进公司级安全框架的法则，
   原始出处是一篇个人博客。**只扫 arXiv 会漏掉这张图的一半骨架。**

2. **反驳边（31）比佐证边（69）少，和越狱那张图正好相反**（那边是 89 对 42）。
   原因不是这个领域更和谐——**是攻击侧几乎没有可争的**：一手披露之间互相印证而不互相反驳。
   真正的分歧集中在防御成色、评测口径与「可不可能被解决」三处，也就是那 11 条战线。

3. **理论泳道是厚的（8 条，含三条独立的不可能性结果）。** 越狱那张图的理论侧几乎空着（只有 3 个点）；
   这里有共享嵌入下的**不可分离定理**、包装式防御的**三难定理**（在 Lean 4 里做过机器验证）、
   以及从**上下文完整性**推出的博弈式不可能。**这三条从两端同时卡死了「分离 + 判定」这条主路线。**
